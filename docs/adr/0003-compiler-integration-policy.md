# ADR-0003：アプリ内コンパイラの選定と同梱方針

**ステータス：採用**

**決定日：2026年10月27日**

## 背景

本アプリケーションでは、利用者が入力したC言語コードをコンパイルし、発生したエラーを日本語で解説する。

コンパイルに成功した場合は、生成したプログラムを実行し、標準入力・標準出力・標準エラー出力を扱えるようにする。

利用者が別途コンパイラをインストールする必要がない構成を目指す。

なお、アプリケーション本体の開発には、ADR-0002で決定したCMake・MSVC・Ninjaを使用する。

## 検討した選択肢

- GCC + MinGW-w64
- Clang + MSVC/UCRT系
- LLVM-MinGW（UCRT版）

## 決定

以下の構成を採用する。

- アプリ内コンパイラ：LLVM-MinGW
- Cランタイム：UCRT
- 対象環境：Windows 11 x64
- 配布方式：アプリケーションへの同梱
- コンパイラのバージョン：動作検証後に固定
- コンパイラおよび生成プログラムの起動：Windows API

## 決定理由

- ClangとLLDを含むWindows向けツールチェーンを利用できる。
- C言語プログラムのコンパイルと実行ファイル生成に対応している。
- UCRTはWindows 11で利用できる。
- コンパイラを同梱することで、利用者による別途インストールを不要にできる。
- コンパイラのバージョンを固定し、エラー診断の一貫性を確保できる。
- アプリ本体のビルド環境から独立して管理できる。

## 実行機能

コンパイル成功後、生成した実行ファイルをWindows APIで起動する。

標準入力・標準出力・標準エラー出力はパイプを用いて処理する。

実行中の停止機能を設け、GUIの応答性を維持する。

## 懸念点と対応

### ライセンス

LLVM-MinGWに含まれる各構成要素のライセンスと再配布条件を確認する。

必要なライセンス文書を同梱し、ソースコード提供などの義務がある場合は適切に対応する。

### 配布サイズ

ツールチェーン全体を同梱すると配布サイズが大きくなる可能性がある。

必要なファイルを調査し、動作を損なわない範囲で構成を検討する。

### 実行時の安全性

利用者が入力したプログラムを実行するため、無限ループ、異常終了、ファイル操作などのリスクがある。

停止処理や実行時間の制限を設ける。ただし、これらだけで安全性が保証されるわけではない。

## 今後の検証事項

- LLVM-MinGWの具体的なリリースとバージョンの選定
- printf、scanf、fgetsを使用したプログラムの動作確認
- コンパイルエラーの取得と解析
- 標準入出力の取得・送信
- 実行停止と異常終了への対応
- 同梱ファイルとライセンス条件の確認
- 開発環境がないWindows 11 PCでの動作確認
