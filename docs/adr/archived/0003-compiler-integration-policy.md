# ADR-0003：アプリ内コンパイラの運用方針

**ステータス：方針案（コンパイラ未選定）**

## 背景

本アプリケーションは、利用者が入力したC言語のソースコードをコンパイルし、出力されたエラーメッセージを解析する。

エラーメッセージはコンパイラの種類やバージョンによって異なるため、使用するコンパイラを明確にする必要がある。

また、学校で使用しているコンパイラに依存しない構成を目指す。

## 決定方針

アプリケーションが呼び出すコンパイラは、開発用コンパイラとは独立して選定する。

利用者のPCにインストールされているコンパイラへ依存するのではなく、アプリケーション側で使用するコンパイラを固定する方針とする。

可能であれば、必要なコンパイラをアプリケーションに同梱する。

## 理由

- 開発用コンパイラとアプリ内コンパイラを分離できる。
- エラーメッセージの形式を統一しやすい。
- コンパイラの種類やバージョンの違いによる解析結果のばらつきを抑えられる。
- 学校のPC環境に依存せず動作させやすい。

## 検討候補

- GCC
- Clang

## 注意点

- コンパイラ本体だけでなく、必要なヘッダーファイルやライブラリなども考慮する。
- 同梱する場合は、ライセンスや再配布条件を確認する。
- コンパイル時の標準出力・標準エラー出力を取得する仕組みが必要となる。
- コンパイラの起動に失敗した場合の処理も必要となる。

## 未決定事項

- GCCとClangのどちらを採用するか
- 使用するコンパイラのバージョン
- コンパイラの同梱方法
- コンパイル時の一時ファイルの管理方法

具体的なコンパイラの選定は、別途比較・検証したうえで決定する。
