# ADR-0005：エラー解説データの管理方式

**ステータス：採用**

**決定日：2026年10月27日**

## 背景

本アプリケーションでは、Clangのコンパイルエラーに対して、事前に用意した日本語解説を表示する。

初期段階では10種類のエラーパターンに対応し、将来的には解説の追加・修正を容易に行える構成を目指す。

また、チーム開発において、エラー解析処理の実装と解説内容の作成を分担しやすくする必要がある。

## 検討した選択肢

- Cソースコードに解説データを直接記述する
- JSONファイルで管理する
- CSVファイルで管理する

## 決定

以下の構成を採用する。

- データ形式：JSON
- JSON解析ライブラリ：cJSON
- 文字コード：UTF-8
- データ管理：アプリケーションとは独立したJSONファイル
- 初期対応数：10種類のエラーパターン

JSONには、エラーの識別子、照合パターン、解説タイトル、説明文、確認ポイントなどを格納する。

## 決定理由

- 解説データとC言語の処理を分離できる。
- アプリケーションを再ビルドせずに解説内容を修正できる。
- エラーパターンの追加やデータ構造の拡張が容易になる。
- 複数の開発メンバーで作業を分担しやすい。
- cJSONはC言語から利用できる軽量なJSON解析ライブラリである。

## データ構造の例

```json
{
  "id": "missing-semicolon",
  "pattern": "expected ';'",
  "title": "セミコロンの不足",
  "explanation": "文の終わりにセミコロンが必要な可能性があります。",
  "checkpoints": [
    "直前の文の末尾を確認してください。",
    "セミコロンが抜けていないか確認してください。"
  ]
}
```

※これは1件分のデータ例であり、ファイル全体の形式は実装時に定義する。

## 実装方針

### データの読み込み

アプリケーション起動時、または必要なタイミングでJSONファイルを読み込む。

cJSONを使用してJSONを解析し、アプリケーション内のデータ構造に変換する。

### データの検証

以下の項目を検証する。

- JSONの構文が正しいこと
- 必須項目が存在すること
- 各項目のデータ型が正しいこと
- エラーIDが重複していないこと
- 文字列が想定する長さを超えていないこと
- 照合パターンが空文字列ではないこと

### パターン照合

ADR-0004で決定した文字列照合方式を使用する。

JSONから読み込んだパターンをClangの診断メッセージと照合し、一致した場合に対応する日本語解説を表示する。

必要に応じて、将来的に正規表現を利用できる構成とする。

### 読み込み失敗時

JSONファイルの欠損や不正なデータがあっても、アプリケーション全体が異常終了しないようにする。

解説データを利用できない場合は、Clangの元の診断メッセージを表示する。

## ライセンス

cJSONはMITライセンスで提供されている。

利用するバージョンを固定し、配布時には必要な著作権表示とライセンス文書を含める。

## 今後の作業

- JSONファイル全体のスキーマを定義する。
- 初期対応する10種類のエラーを選定する。
- cJSONの導入方法とバージョンを確定する。
- JSONの読み込み・検証処理を実装する。
- パターン照合処理と連携する。
- 不正なJSONや重複IDに対するテストを作成する。
