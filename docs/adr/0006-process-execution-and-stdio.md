# ADR-0006：プロセス実行と標準入出力の管理方式

**ステータス：採用**

**決定日：2026年10月27日**

## 背景

本アプリケーションでは、利用者が入力したC言語コードをコンパイルし、成功した場合は生成したプログラムを実行する。

実行結果をアプリケーション内に表示するほか、scanfやfgetsなどの標準入力を利用するプログラムにも対応する必要がある。

一方、本アプリケーションの主目的はコンパイルエラーの理解支援であり、本格的なターミナル機能の実装は目的としない。

## 検討した選択肢

- Windows APIとパイプを使用し、実行中に標準入力を受け付ける
- Windows APIとパイプを使用し、実行前に標準入力を設定する
- Windows疑似コンソール（ConPTY）を使用する
- 外部コンソールウィンドウで実行する

## 決定

以下の構成を採用する。

- プロセス起動：Windows API（CreateProcessW）
- 標準入出力：匿名パイプ（CreatePipe）
- 標準入力：実行前に利用者が設定したテキストを自動送信する
- 標準出力：パイプから取得してアプリ内に表示する
- 標準エラー出力：パイプから取得してアプリ内に表示する
- プロセス監視：UIスレッドとは別に実行する
- 実行停止：利用者が停止操作を行えるようにする

標準入力は、改行を含む自由なテキストとして設定できるようにする。

実行中に追加の標準入力を送信する機能は、初期実装の対象外とする。

## 決定理由

- scanfやfgetsなどを使用する基本的なC言語プログラムに対応できる。
- 実行中の入力操作を管理する必要がなく、UIと処理を簡素化できる。
- 同じ入力値を使って繰り返し実行でき、学習や動作確認に適している。
- Windows APIを使用するため、追加のプロセス実行ライブラリを導入する必要がない。
- アプリケーション内で標準出力と標準エラー出力を取得できる。

## 実装方針

### プロセスの起動

CreateProcessWを使用して、コンパイル後の実行ファイルを子プロセスとして起動する。

標準入力・標準出力・標準エラー出力をパイプに接続する。

### 標準入力

利用者が実行前に入力したテキストを、子プロセスの標準入力に送信する。

送信処理にはWriteFileを使用する。

入力の送信が完了したら、標準入力パイプの書き込み側を閉じ、EOFを通知する。

入力データが大きい場合にも処理が停止しないよう、標準出力・標準エラー出力の読み取りと並行して送信する。

### 標準出力・標準エラー出力

ReadFileを使用して、子プロセスの標準出力と標準エラー出力を取得する。

取得した内容はUIスレッドへ通知し、アプリケーション内に表示する。

コンパイラの診断メッセージと、利用者プログラムの実行結果は区別して管理する。

### プロセスの監視と停止

実行中のプロセスを監視し、終了時には終了コードを取得する。

利用者による停止操作を用意する。

無限ループなどに備えて、実行時間の上限を設ける。

必要に応じてJob Objectを利用し、子孫プロセスを含む終了管理を検討する。

### GUIの応答性

プロセスの起動・監視・入出力処理は、UIスレッドをブロックしないように実装する。

## 制約と懸念点

### 対話型プログラム

実行中に追加の入力を送信することはできない。

利用者の回答に応じて次の入力を決めるプログラムには適さない。

### 入出力のバッファリング

標準出力がパイプに接続されることで、printfなどの出力がすぐに表示されない場合がある。

通常のコンソールと完全に同じ動作は保証しない。

### 実行時の安全性

利用者が入力したコードを実行するため、ファイル操作や外部プロセス起動などの副作用が発生する可能性がある。

タイムアウトや停止機能だけでは、実行環境の安全性は保証されない。

### 文字コード

標準入力の文字コードと、プログラムから出力される文字列の文字コードについて、Windows環境での動作を検証する。

- 標準出力・標準エラー出力の並行取得
- プロセス終了コードの取得
- 停止操作とタイムアウト処理の実装
- 大量入出力や入力不足時の動作確認
- GUIスレッドとの連携方法の設計
