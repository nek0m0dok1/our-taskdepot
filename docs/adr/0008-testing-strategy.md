# ADR-0008：テスト戦略とテスト環境

**ステータス：採用**

**決定日：2026年10月27日**

## 背景

本アプリケーションは、C言語初学者向けのコンパイルエラー解説ツールである。

GUI、コンパイラ制御、エラー解析、解説データ管理、プログラム実行など、複数のモジュールから構成される。

チーム開発において各機能の品質を確認し、変更による不具合を早期に発見できるテスト環境が必要である。

## 検討した選択肢

- CTest + 自作テストプログラム
- CTest + Unity
- 手動テスト中心

## 決定

以下のテスト構成を採用する。

- テスト実行・管理：CTest
- C言語の単体テスト：Unity Test Framework
- 結合テスト：CTestから実際のコンパイラや実行プログラムを呼び出して検証
- GUIテスト：手動チェックリストによる確認

テスト環境はADR-0002で決定したCMake・MSVC・Ninjaのビルド構成に統合する。

## 決定理由

- CTestはCMakeと連携でき、既存のビルド構成に組み込みやすい。
- UnityはC言語向けの軽量なテストフレームワークである。
- テストケースを整理し、失敗箇所を把握しやすくなる。
- モジュールごとの単体テストを実施できる。
- 実際のLLVM-MinGWを使用した結合テストで、コンパイラや実行制御の問題を検出できる。
- GUIの操作性や表示については、手動確認を組み合わせることで補完できる。

## テスト方針

### 単体テスト

Unityを使用して、GUIや外部コンパイラに依存しない処理を検証する。

主な対象は以下とする。

- エラー診断メッセージの解析
- エラーパターンの照合
- JSONファイルの読み込みと検証
- 共通処理やデータ変換

### 結合テスト

CTestを使用し、複数のモジュールを連携させた動作を検証する。

主な対象は以下とする。

- LLVM-MinGWによるコンパイル成功・失敗
- コンパイルエラーの取得と解説への変換
- 生成した実行ファイルの起動
- 事前設定した標準入力の送信
- 標準出力・標準エラー出力の取得
- 異常終了・タイムアウト・停止処理

### GUIテスト

チェックリストを用いて、実際のWindows 11環境で動作を確認する。

主な対象は以下とする。

- ソースコードの入力・編集
- Cファイルの読み込み
- コンパイルエラーの表示
- 日本語解説の表示
- 標準入力の事前設定
- 実行結果の表示
- 実行中の停止操作
- 画面の表示崩れや操作不能の有無

## テストデータ

正常なCコード、コンパイルエラーを含むCコード、標準入力を使用するCコードなどをテストデータとして管理する。

初期対応する10種類のエラーパターンについて、それぞれ一致するケースと一致しないケースを用意する。

## テスト実行

CMakeのテスト設定を有効にし、CTestからテストを実行できるようにする。

共通のCMakePresets.jsonにテスト用プリセットを定義し、開発メンバーが同じ手順でテストを実行できる構成を目指す。

## 懸念点と対応

### テスト環境の差異

コンパイラのバージョンや実行環境によって、診断メッセージやプログラムの動作が異なる可能性がある。

ADR-0003で決定したLLVM-MinGWのバージョンを固定し、テスト環境を統一する。

### GUIテストの自動化

Win32 APIを使用したGUIの自動テストは、初期段階では導入負担が大きい。

まずは手動チェックリストによる確認を採用する。

### テスト実装の負担

テストを一度に整備しようとすると、機能開発が遅れる可能性がある。

重要なモジュールから段階的にテストを追加する。
