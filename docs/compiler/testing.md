# 異常系とテスト

更新日：2026-11-04。状態：合意済みの検証計画・実行未実施。対象：Compilerの受け入れ条件。

## 失敗時の原則

利用者のCコードの誤りと、起動・内部処理の失敗を分ける。状態の正本は[結果状態の表](interface.md)。一時ファイル生成失敗・プロセス管理失敗・終了コード0で出力なしは内部エラーとする。

異常時にも子プロセスを不必要に残さず、パイプ・ハンドル等を解放し、不要ファイルを回収する。不完全な出力を渡さず、誤った成功表示をしない。競合しても結果や後片付けを二重に確定しない。

## 検証方法

正常系・異常系を自動テストし、既存CMake・CTestへ統合する。実際のLLVM-MinGWを使う結合テストと、失敗を再現する代替プロセスのテストを組み合わせる。基盤の変更がGUI・実行・解析へ及ぼす不具合を繰り返し検出するためである。

既存[ADR-0008](https://github.com/nek0m0dok1/our-taskdepot/blob/main/docs/adr/0008-testing-strategy.md)に合わせ、C単体テストはUnity、GUI操作は手動チェックリストで補完する。

| 分類 | 必須の確認 |
|---|---|
| 正常 | 有効なCコード、実行ファイル生成、成功状態、終了コード取得・有効性、出力パス、一時ソース削除 |
| 入力・失敗 | 構文エラー、空文字列の受け渡し、NULL拒否、起動失敗、タイムアウト、中断 |
| 出力・回収 | 不完全な出力を渡さない、終了コード0で出力なしは内部エラー、一時ファイル削除、削除失敗の通知 |
| 日本語環境 | 日本語・空白パス、UTF-8診断、不正文字の置換、文字境界での切り詰め |
| 負荷・競合 | 1MiB超のログ、大量ログ中のタイムアウト、処理中の中断、自然終了との競合、子プロセスが残らない |
| 起動時回収 | 異常終了後の回収、使用中領域を削除しない、安全な対象判定、回収時間の制約 |
| 連携 | GUIの応答性、編集・再開始の制限、完了通知と状態に応じた解析への引き渡し |

## 完成条件

テストの存在だけでは完了としない。Windows 11でビルドでき、既存を含むCTestが成功し、同梱予定LLVM-MinGWで合意した期待結果を確認する。未実施・失敗は明示する。

実装の完成には、同梱Clangによるコンパイル、利用可能な成功出力、正確な失敗状態と診断、タイムアウト・中断、GUIを止めない非同期実行、定めた資源管理、日本語環境、自動テストと実機検証のすべてを満たす必要がある。

タイムアウトやJob Objectだけで利用者コードの安全性を保証しない。利用者プログラムの実行そのものはCompilerの対象外。検証結果はIssueや検証記録へ残す。
