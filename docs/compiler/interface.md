# インターフェースと結果状態

更新日：2026-11-04。状態：合意済み設計・公開名は既存ヘッダーと要照合。対象：モジュール間契約。

## 入力と設定

- ソースはUTF-8文字列。GUIが一時ファイルを作らず渡せるようにする。
- 空文字列は有効で、実際のコンパイラへ渡す。学習時に自然な入力を独自エラーにしないため。NULLは呼び出し誤りとして拒否する。
- 設定全体がNULLなら既定設定。タイムアウト既定値は10,000ms、設定値0も既定値を意味する。
- コンパイラパスの明示指定を優先する。未指定ならアプリ実行ファイル基準で同梱Clangを解決し、PATHには依存しない。環境ごとのコンパイラ・診断差を避けるため。
- Windows APIのパスはワイド文字列で扱い、ソースとの文字コード差を内部で適切に変換する。空白・日本語パスに対応する。

## CompileResult

関連情報と所有権をまとめるため、結果は構造体で扱う。

| フィールド | 契約 |
|---|---|
| `status` | 下表の処理結果分類 |
| `exit_code` | Windowsプロセスの終了コード |
| `has_exit_code` | 終了コードが有効か。未起動時などと取得済みの0を区別する |
| `diagnostics` | UTF-8の診断・起動時エラー情報。ログがなければ空文字列 |
| `logs_truncated` | ログ保存上限による欠落があることを示す |
| `output_path` | 成功し、後続で利用可能な出力を確認した場合だけ有効。それ以外はNULL |
| `cleanup_failed` | コンパイル自体の成否と独立した後片付け失敗 |

| 状態 | 意味 |
|---|---|
| `COMPILE_SUCCESS` | コンパイル成功 |
| `COMPILE_ERROR` | コンパイラがコンパイル失敗を報告 |
| `COMPILE_TIMEOUT` | 制限時間超過 |
| `COMPILE_CANCELLED` | 利用者による中断 |
| `COMPILE_LAUNCH_ERROR` | コンパイラ起動失敗 |
| `COMPILE_INVALID_ARGUMENT` | NULLなどの不正引数 |
| `COMPILE_INTERNAL_ERROR` | 一時ファイル生成・プロセス管理等の内部失敗 |

状態名は設計上の識別名。最終的な命名は既存公開ヘッダーと統一する。終了コードだけでは起動失敗・中断等を分類できないため、`status`と分ける。

終了コード0でも実行ファイルがなければ`COMPILE_INTERNAL_ERROR`。後続で使える出力なしに成功を返さない。

## 解析への引き渡し

日本語のC言語エラー解析は`COMPILE_ERROR`だけで行う。成功時の警告はGUIに表示するが解説しない。他の状態も解析へ渡さない。`diagnostics`にはWindowsエラー文も入るため、非空かどうかで判断しない。

文字列の所有権は[資源管理](resources.md)、ログの形式は[診断ログ](diagnostics.md)参照。
