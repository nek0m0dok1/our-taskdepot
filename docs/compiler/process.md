# プロセス制御と非同期連携

更新日：2026-11-04。状態：合意済み設計・実機検証前。対象：起動、監視、中断、GUI連携。

## 起動と終了管理

`CreateProcessW`でClangを起動し、日本語を含むUnicodeパスに対応する。存在の事前確認は必須にせず、実際の起動結果を成否の基準にする。確認後の状態変化や、存在しても起動不能な場合があるためである。

起動失敗時はWindows APIのエラー情報を読みやすいUTF-8メッセージへ変換し、結果に含める。Compilerがダイアログを直接表示しない。

Job Objectで関連プロセスをまとめて管理し、Clangだけ停止して子プロセスが残ることを防ぐ。コンパイラが動き始める前に管理対象へ登録し、起動と登録の間に管理外の実行時間を作らない。

## タイムアウトと中断

- 既定10秒。学習用の短いコードで長時間待たせないため。環境差に備え、呼び出し側が時間を変更できる契約を維持する。
- 超過時は管理対象プロセスの停止を要求し、停止確認後に回収して`COMPILE_TIMEOUT`を返す。
- Ctrl+CはGUIが検知し、非同期制御を通じてCompilerへ伝える。Compilerが停止・停止確認・後片付けを行い、`COMPILE_CANCELLED`を返す。
- 自然終了・タイムアウト・中断の競合で、矛盾する結果や二重の後片付けを発生させない。具体的な同期機構は実装時に選定する。

GUIが直接プロセスを停止すると管理責務が重複するため、起動と停止はCompilerに集約する。

## 非同期制御

Compilerは同期的に結果を返し、独立した非同期制御モジュールが別スレッドで呼ぶ。同モジュールがワーカー開始・管理、中断伝達、結果受領、UIスレッドへの安全な完了通知を担う。

GUIやCompiler自身にスレッド管理を持たせる案は採用しない。責務を分け、GUIなしのテストと将来の再利用を可能にするためである。

## コンパイル中のGUI

編集と新たなコンパイル開始を禁止する。表示中のソースとコンパイル対象の食い違いを防ぐためである。ウィンドウ操作・状態表示・中断は可能とし、応答性を維持する。

診断ログは終了後にまとめて表示し、初期GUIと連携を簡潔にする。内部のパイプ読み取りは実行中も続ける（[診断ログ](diagnostics.md)）。

ウィンドウ終了操作では確認する。「終了する」なら停止・後片付けを試みて終了し、「戻る」ならコンパイルを継続する。強制終了・電源断の残骸は[起動時回収](resources.md)へ委ねる。
