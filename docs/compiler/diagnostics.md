# 診断ログと文字コード

更新日：2026-11-04。状態：合意済み設計・変換方式は実機確認前。対象：Compilerの出力情報。

## パイプと保存上限

Clangのstdoutとstderrを同じパイプへ接続する。二つを別々に管理するより初期実装を簡潔にできる。一方、出力元の区別と厳密な出力順序は保証しない。

終了待ちと並行して、実行中からパイプを継続的に読む。終了後まで待つと、満杯のパイプへの書き込みでコンパイラが停止し、終了待ちも進まなくなるためである。

保存上限は1MiB（1,048,576バイト）。超過分は保存せず、`logs_truncated`を有効にする。上限到達後も読み取りは継続して、プロセスを詰まらせない。メモリ消費を制御しつつ、呼び出し側へログが不完全なことを伝える。

## UTF-8の契約

- 返す診断情報はUTF-8へ統一し、GUI・解析側の個別変換を不要にする。
- 変換不能な箇所はU+FFFDへ置換する。
- 切り詰め時にもUTF-8の文字境界を守る。
- 実際のClangの診断出力条件を実機確認し、変換方式を固定する。任意のバイト列から元の文字コードを完全には判定できない。

UTF-8を返す方針は確定しているが、使用するClangの出力文字コードを確認済みとは扱わない。

## 空ログとシステムエラー

ログがなければ`diagnostics`は空文字列。GUIは「診断ログの出力はありませんでした。」と表示する。Compilerがこの文言をログへ追加しない。実際の出力と表示用の文章を区別するためである。

起動失敗時のWindowsエラー情報も`diagnostics`へUTF-8で格納する。C言語エラー解析の条件はログ内容ではなく[結果状態](interface.md)に従う。GUIに表示しない内部エラーについても、検証に必要な情報を失わないようにする。
