# 概要

更新日：2026-11-04。状態：合意済み設計の再構成・実装前。対象：Compilerの責務。

CompilerはC言語ソースを受け取り、Windows実行ファイルの生成を試みる。成功時は利用可能なファイルの場所、失敗時は種類と診断情報を返す。利用者プログラムの実行、診断の解析、日本語解説の生成は担当しない。

## 処理と分担

1. GUIが要求を非同期制御へ渡す。
2. 非同期制御がワーカースレッドでCompilerを呼ぶ。
3. Compilerが入力検証、一時ソース生成、コンパイラパス解決、起動、ログ収集、終了・中断・タイムアウト判定、後片付けを行い、`CompileResult`を返す。
4. 非同期制御がUIスレッドへ安全に完了通知する。
5. GUIが結果を表示し、成功時は実行モジュール、コンパイルエラー時は解析モジュールへつなぐ。

| 担当 | 責務 |
|---|---|
| GUI | 入力・表示、編集制限、中断操作の検知、終了確認 |
| 非同期制御 | ワーカー管理、要求・中断の伝達、完了通知と結果受け渡し |
| Compiler | コンパイラと資源の管理、ログ・終了コード取得、結果生成 |
| 実行制御 | 生成した利用者プログラムの実行 |
| エラー解析 | 診断情報の解析と日本語解説への連携 |

CompilerはGUIへ直接依存しない。機能を分けることでGUIの変更の影響を抑え、GUIが未完成でもCompiler単体を開発・テストできる。

## 優先順位

正しくコンパイルできること、失敗時もアプリが停止しないこと、明確なモジュール間契約、日本語環境での安定性、資源管理、初学者中心のチームでの保守性の順に重視する。高度な汎用性より、今回必要な動作の安定性を優先する。
