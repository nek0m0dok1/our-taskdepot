# 一時ファイルとメモリ管理

更新日：2026-11-04。状態：合意済み設計・安全性検証前。対象：ファイルと動的メモリの寿命。

## 作業領域と通常の後片付け

Windows一時ディレクトリ内のアプリ専用領域に、コンパイルごとの固有ディレクトリを作る。ファイル衝突を防ぎ、回収対象を識別しやすくする。CompilerがソースをUTF-8の`.c`ファイルとして保存する。

| 状況 | 後片付け |
|---|---|
| 成功 | 一時ソースと不要な作業ファイルを削除し、完成した実行ファイルは保持 |
| コンパイル失敗・起動失敗 | 作成済みの不要ファイルと不完全な出力を回収 |
| タイムアウト・中断 | 管理対象プロセスの停止確認後に回収 |
| 強制終了・電源断 | 次回起動時に回収 |

通常の削除は1回だけ試み、再試行しない。失敗は`cleanup_failed`で通知し、コンパイル結果と混同しない。次回起動時の回収は、通常削除とは別の回復処理である。

## メモリと実行ファイルの所有権

Compilerが結果文字列の領域を確保し、呼び出し側が専用解放関数で解放する。呼び出し側が内部の個々の確保領域を判断せずに済み、内部構造を変更しても解放方法を統一できる。

実行ファイルの削除はメモリ解放から分離する。呼び出し側が保持期間を管理し、不要になった際にCompilerの専用削除処理を呼ぶ。後続の実行モジュールが使うため、成功直後には削除しない。

結果を解放してから出力を使う場合、先に必要なパス情報を保持する。解放済みのパス文字列を参照し続けない。

## 次回起動時の安全な回収

メイン画面表示前に実行する。削除対象は、アプリ専用領域内・アプリの管理情報で識別可能・使用中でない、と確認できたものに限る。リンクやパスによる領域外の誤削除を防ぎ、安全性不明なら削除しない。不要ファイルが残ることより、無関係なファイルを消さないことを優先する。

回収は最大3秒を目安とし、超過後は新たな回収操作を開始しない。開始済みの個別ファイル操作まで3秒以内に終わる保証はしない。

回収失敗時はGUIで「前回の作業で作成された一時ファイルの一部を削除できませんでした。アプリの使用を続行しますか？」と警告し、「続行」「終了」を選べる。安全な新規作業領域も確保できない場合は続行を許可しない。

初期版は複数同時起動を禁止し、名前付きミューテックスなどを使う方針とする。別インスタンスが使用中のファイルを誤回収する危険を減らすためであり、使用中確認自体は省略しない。
